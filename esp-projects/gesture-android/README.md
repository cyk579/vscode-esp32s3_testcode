# KS-21创新 · 安卓全向小车控制端

一个 APP 提供横屏双摇杆、手机中文语音和车载音乐控制，手势模块独立接入。当前版本 **1.9-ks21（versionCode=10）**。桌面名称与应用标题统一为 **KS-21创新**，使用海军蓝背景、白色与青绿色 KS 字标的原生矢量自适应图标，支持 Android 13 单色主题图标。包名与签名不变，可覆盖安装保留数据。硬件、完整方案与验收见 [subject3-ASR](../subject3-ASR/README.md)，组员分工与接口见 [FEATURES.md](FEATURES.md)。

## 构建

Android Studio 打开本目录，或使用 JDK17、Android SDK Platform35：

```powershell
.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
```

沿用 AGP8.7.3、Kotlin2.0.21、Gradle8.10.2、minSdk26、targetSdk35。Wrapper 带发行包 SHA256 校验。SDK 路径在本机 Android Studio、`ANDROID_HOME` 或 `local.properties` 配置，勿照搬或提交其他电脑的绝对路径。

APK：`app/build/outputs/apk/debug/app-debug.apk`；合并版交付副本：`../app-debug-landscape.apk`。新 APP 兼容旧 OMNI-2 车端的运动服务，横屏控制无需重刷车端；音乐需要 `subject3-ASR` 固件、音乐分区、音频硬件和匹配的 APP 曲库。

## 使用

1. 手机打开蓝牙，点击右上角“连接车辆”，在弹窗中扫描并连接自己的车（默认组号 1）。徽章显示“已连接”后，等 IMU 正常、车辆 READY，再操作。
2. “双摇杆”页采用横屏驾驶舱：左杆前后/左右平移，右杆左右旋转，中间常驻车辆状态、输入百分比、急停和解除。任一杆松开都停车，全部松手后重新触摸。
3. “语音”页点击“说运动指令”，对手机说“前进、后退、左移、右移、左转、右转”。平移目标时长 3 秒，左右转 0.5 秒。支持“先前进再左移再左转”，最多 6 步，支持“再 / 然后 / 接着”及逗号分隔；组合中“旋转 / 原地旋转”默认右转。整句必须全部匹配，包含否定、未知动作或超长序列时整组不执行；“停车”只能作为最后一步。点一次听一次，没有持续监听。
4. “音乐”页可直接选曲，或点击“语音点歌”说“播放测试音”。只播放已导入曲库的歌曲，默认仅含测试音。导入方式见 [本地曲库](../subject3-ASR/music/README.md)。音乐页不执行运动语音。
5. 语音“停止”只停车，“停止音乐”才停止歌曲。页面切换、急停、BLE 断开和切后台不停止车端已开始的播放。
6. 急停后须手动解除，再重新启用运动。切后台、锁屏后 BLE 断开，返回需重新连接。

组合指令逐步显示进度；步骤间至少停车 350ms 并等待车端 READY，等待超过 2 秒取消剩余步骤。切换模式、新一轮语音输入、急停、断连、故障、状态超时和界面失焦均取消整组，不会恢复旧动作。执行调度中断超过 250ms 也会取消，不补执行遗漏步骤。时长是指令持续时间，不保证精确位移或角度；先架空车轮验证，再在空旷区域低速测试。

首次权限授权可能引起应用暂停；授权后重新连接、再点击。系统中文语音服务缺失或模型不可用时保持停车；可切换到系统语音服务重试，可能需要网络。歌曲外放对手机采音的影响需真机验证。

### 手势掌心控制（1.8-gesture-guidance / versionCode 9）

预览占据手势区域完整高度，操作和诊断移到侧边，保留 FIT_CENTER，不裁剪摄像头画面。显示尺寸不改变识别坐标或摄像头视野。任一指尖超出图像范围会保持停车并要求完整入镜；握拳不需要张掌定中，所以握拳能转不代表张掌已通过验证。侧边明确显示出界、低置信度、超时、未知手势及定中进度，不再统一显示含糊的定中提示。请将手移远，让五指完整入镜且四周留出移动空间。

点击“启用手势”，张开手掌并静止约半秒，画面上的绿色十字表示本轮中立位置。掌心相对十字向画面上方移动为前进、下方为后退、左方为左移、右方为右移；不是向镜头靠近/远离的深度控制。回到十字附近停车，握拳保持原地旋转请求并触发曲库首曲（需要车端支持音乐）。重新启用可重新定中。

使用手腕及四个掌指关节的平均位置作为掌心；相对移动达到图像宽/高约 18% 即可满量程，避免必须把整只手移出画面才能有效控制。丢失手、低置信度、过期图像时停止运动；重新出现张掌须再次静止定中。所有运动仍需 BLE 已连接、车端就绪且无急停/IMU 故障。

关键点与显示位图来自同一次推理；图像只在送入模型前旋转及镜像一次，21 点骨架使用 ImageView 的实际 imageMatrix 绘制，包含 FIT_CENTER 黑边及 padding，不会再次镜像。摄像头图像在手机本地推理，不上传。旧版 `(0.5 - 坐标) * 50` 在坐标 0..1 内本来就是 ±25，之前“±50 越界导致单向控制”的诊断不成立；本轮修复的是参考点偏置、可达范围及预览坐标。

JVM 测试验证四方向、定中、丢手、时效和 BLE 字段；`gradlew.bat :app:connectedDebugAndroidTest` 在手机验证骨架与 FIT_CENTER 画面（含黑边/内边距）的对齐及清除。真机运动须先架空车轮验证，测试通过不等同于带载轮速或识别准确率验收。

## 横屏与安全

应用支持两个横屏方向，不使用竖屏驾驶。驾驶双摇杆区域不可滚动；连接弹窗的设备列表、语音/手势/音乐页可滚动。系统栏默认隐藏，可从屏幕边缘滑动临时唤出；控件为刘海和系统栏预留边距。

打开连接弹窗、失去窗口焦点、布局尺寸或安全边距变化、左右翻转时会撤销输入并释放两个摇杆；回到界面不会自动续发之前的运动指令。翻转若导致界面重建会断开 BLE。切后台和锁屏仍断开 BLE。

运动心跳每 50ms，单个 GATT 操作在途，200ms 无回调则断开；音乐短命令排在到期运动帧之后。运动仲裁、BLE、语音和音乐分别由独立模块负责，保留车端故障保护及失联停车。

## 验证边界

本次合并需运行 Android 单元测试、Gradle APK 打包、Lint，以及 `gesture-common`、`subject3-ASR` 主机测试。构建通过不等同于真机验收；Android 权限、语音服务、触摸/BLE 和实车音频仍需在目标设备验证。

真机验收先架空车轮，连接并回中后依次测试双杆及双指组合、任一松手、连接弹窗、页面切换、急停、切后台、左右翻转和临时唤出系统栏；任何中断后都不得自动恢复运动。再验证语音运动超时停车、选曲/语音点歌、暂停/继续/停止音乐、音乐播放时急停及断连。大字体、刘海和系统导航表现需按实际手机确认。
