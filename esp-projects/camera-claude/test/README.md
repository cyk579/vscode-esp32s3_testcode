# host 端测试

本机没有 idf.py，所以用 gcc 做两件事：

1. **合成画面回归**：`harness.c` 直接编译 `main/line_detect.c`、
   `main/line_control.c`、`main/line_mixer.c`（都是纯 C，不含 ESP 头文件），
   画出各种赛道场景断言输出符号。
2. **语法检查**：`esp_stubs/` 里是最小的假 ESP-IDF 头文件，让 gcc 能对
   `line_follow.c`、`camera_display.c`、`ultrasonic.c` 做 `-fsyntax-only`。

```bash
bash build.sh
```

## 测什么

符号和数量级，不测具体数值。符号错了车会直接冲出赛道，这是唯一能在没有实车
的情况下抓到的一类 bug；而速度、增益只能在赛道上调。

覆盖的场景：直道居中 / 左右平行偏移 / 左右倾斜 / 左 90° 直角弯 / 右锐角急弯 /
全白（丢线）/ 全黑（阈值漂移）/ 窗口外干扰暗块 / 丢线后窗口扩张 /
120x80 与 160x120 的千分比一致性 / 混控起转值与 PWM 上限 / 丢线找线方向。

关键的三条断言：

- 平行但偏右时 `heading` 落在死区内 —— 这是 `heading = far_x - near_x` 而不是
  `far_x - 中心` 的意义，否则车会左右振。
- 左 90° 弯时 `heading` 明显为负、`turn` 为正（逆时针 = 左）—— 弯道不需要专门
  识别，靠的就是这条。
- 原地旋转 `turn = 15` 时三个轮子都超过实测起转值（A/D 11、B 13）—— 否则车
  会卡住不转。

## 局限

跑通**不代表**车能巡线。合成画面是理想的：没有反光、没有阴影、胶带边缘是硬的、
阈值给死在 110。真实的失败模式（曝光、抖动、静摩擦、电池电压下降）只能在赛道
上看 TFT 叠加层排查。
