# 单 S3 + 安卓手机体感推球小车

本实验用安卓手机倾角控制前进、后退、转向，由操作者目视对准球，借助车头轻质挡板低速推球。没有评分、视觉找球或独立击球舵机。车端使用一块 **ESP32-S3 / ESP-IDF 5.5.4**，手机通过 BLE 发送控制帧，已有巡线与推球工程不被改写。

| 方案 | 控制端 | 车端设置 | MPU6500 位置 |
| --- | --- | --- | --- |
| 当前方案 | `gesture-android` 安卓应用 | `ENABLE_CAR_IMU=1`（默认） | 小车 |

无线链路使用 ESP32-S3 内置 BLE；BT08B、DHT11 不参与。不需要第二块 ESP32-S3，也不需要蓝牙串口助手。

## 从哪里开始

1. 先读 [接线表](WIRING.md)，核对车端 `main/board_pins.h`。电机和 MPU6500 已按创新实验表配置；如果实测排针与表格不同，先修改引脚并重新构建。
2. 保持 `ENABLE_CAR_IMU=1`；当前 MPU6500 使用 GPIO17=SDA、GPIO3=SCL。GPIO1/2 恢复摄像机两个舵机信号，编码器 E2A/E2B 不接。`ENABLE_TFT` 默认 0；打开时还需确认屏幕五个 GPIO。
3. 在 ESP-IDF 5.5.4 终端构建车端，再构建 [安卓端](../gesture-android/README.md)。车端说明见 [车端](../gesture-car/README.md)。
4. 按下文顺序校准、架空验证，再低速落地推球。初始方向和起转占空比取自仓库既有三轮小车代码，仍需要实车确认。

## Windows 中文路径构建

部分 Windows 工具对中文路径支持不完整：Python 需要 UTF-8，Xtensa 的 `objdump` 在链接阶段仍可能找不到路径，Gradle 的测试类加载也可能失败。因此当前仓库位置推荐从根目录使用英文缓存构建脚本：

```powershell
# 在已激活的 ESP-IDF 5.5.4 终端执行：
python esp-projects/gesture-common/build.py car

# 已配置 JDK17 和 ANDROID_HOME 的终端执行：
python esp-projects/gesture-common/build.py android
```

脚本按源码内容生成英文缓存快照，默认放在用户目录 `.cache/gesture-builds`。用户名本身含中文或空格时，通过 `--cache-root C:/gesture-builds` 指定英文路径。它不修改原工程引脚；输出源码 SHA256 清单，成功后把固件或 APK、日志和结果复制回相应工程的 `build-local/verified/default`。

脚本使用版本化的 `sdkconfig.defaults`，不复制本机生成的 `sdkconfig`。使用此方式设置组号或板型时，请在相应 `sdkconfig.defaults` 中设置，例如 `CONFIG_GESTURE_GROUP_ID=2`，避免只修改本机 menuconfig 而未传入快照。烧录可进入脚本打印的英文快照项目目录，在同一 ESP-IDF 终端执行 `idf.py -B build-local -p 实际串口 flash monitor`。

`--car-imu 0/1`、`--tft 0/1` 是编译变体验证参数，不改变原工程引脚；各变体的产物分目录存放。实际使用前仍应根据万用表和板卡丝印核对 `board_pins.h`，再重新构建。

## 操作与状态

前后倾角的正方向为前倾；左右倾角的正方向为左倾。倾角不是绝对航向，也不估计小车位置。

| 状态码 | 名称 | 含义 |
| --- | --- | --- |
| 0 | OFF | 未连接，无驱动输出 |
| 1 | WAIT_NEUTRAL | 松开使能并回正，连续保持至少 300ms |
| 2 | READY | 已收到有效中立状态，可以按下使能 |
| 3 | ACTIVE | 按住使能期间按倾角行驶 |
| 4 | FAULT | 数据无效、姿态超限、通信超时或车端故障，已撤销驱动 |

- 按住手机屏幕使能按钮后，前倾前进、后倾后退、左倾左转、右倾右转，组合倾斜为弧线运动。
- 保持按键并回正是正常斜坡减速；松手、急停、断连或故障绕过斜坡，将 PWM 清零并将 STBY 拉低。这里的“停车”是撤销电机驱动，车体仍可能因惯性滑行。
- 新连接、超时、故障恢复及松手后，都需要松手回正再按下；持续按着屏幕按钮重连不能恢复驱动。
- 第一版 BLE 以组号筛选设备，默认组号 1。车端在 `menuconfig → Gesture experiment` 设置后，安卓端的 `Protocol.GROUP_ID` 要一致。组号不是身份认证或密码，不实现绑定和加密配对。
- 手机倾角任一轴超过 60°禁止驱动；车体横滚或俯仰超过 30°持续 200ms 禁止驱动。MPU 数据超过 100ms 未更新即无效。

## 参数与算法

参数集中于 `include/control_config.h`。初值：5°死区、25°满指令、单轮 PWM 上限 30%、输出斜坡每秒 60 个占空比百分点、控制超时 250ms、换向零输出至少 20ms。这些是调试起点，不代表实际车速。

车体混控复用仓库 `camera-test` 的前进/旋转几何关系，横移输入固定为 0：`A=-forward-turn, B=turn, D=forward-turn`。超限时整组等比缩放。电机驱动再应用 A/B/D 极性，初值为 `1,1,-1`。

A/D 初始起转阈值 11%、B 为 13%。小于阈值的 PWM 置零，不添加起转冲击；这意味着非常小的手势可能不动车，也意味着起转附近仍有机械死区。先逐轮测量带负载起转值，再调整这些参数。第一版没有编码器速度闭环，斜坡限制的是 PWM 指令，不能保证真实加速度恒定。

MPU6500 使用 I2C，自动探测 0x68/0x69，`WHO_AM_I` 必须为 0x70。配置 100Hz、±8g、±500°/s，DLPF 约 20Hz；加速度换算系数 4096 LSB/g，角速度 65.5 LSB/(°/s)。与 MPU6050 驱动不能直接混用。硬件依据为 TDK/InvenSense MPU-6500 Register Map（RM-MPU-6500A-00）。

上电在水平静止条件下积累约 2 秒陀螺零偏，随后等待 Fusion 约 3 秒收敛；移动或安装方向不正确会继续等待。采样中断后重新进行校准。单姿态校准不等于完整加速度计多面校准。

`gesture_imu` 把传感器轴转换成 **X 前、Y 左、Z 上** 的右手坐标系；`IMU_AXIS_* / IMU_SIGN_*` 必须构成旋转，不能构成镜像。姿态使用固定版本的 [Fusion](third_party/Fusion/UPSTREAM.md) 无磁力计算法，保留 MIT 许可。手机应用将校准后的旋转矢量转换为相同的前后、左右倾角语义。

## 代码结构与线程边界

- `gesture_protocol`：纯 C 编解码及序号判断。
- `gesture_control`：纯 C 状态机、死区映射、等比混控、斜坡和换向间隔，可直接在 PC 上测试。
- `gesture_imu`：I2C 采样任务，短临界区发布完整姿态快照，其他任务不会直接读取 I2C。
- `gesture_ble`：车端 GATT 服务。手机端只保持一条未完成的写请求，传输停滞 200ms 后断开，避免排队回放旧控制指令。
- 车端 BLE 回调在短临界区提交状态；100Hz 驾驶任务是正常运行中唯一写电机的任务。松手/断连后，正常调度下在下一个控制周期（约 10ms）撤销驱动；无线失联兜底约为 250ms 加一个控制周期。
- 安卓所有界面、姿态状态、GATT 回调处理和发送都串行到主线程；50ms 发送循环只使用最新姿态。应用暂停时释放使能并断开。
- 可选 TFT 使用现有 ST7735 文本驱动的独立副本，5Hz 显示状态、故障和请求 PWM。显示初始化或传输失败后停止屏幕刷新，不停止驾驶任务。BLE 状态中的 PWM 是斜坡后的请求值，尚未扣除电机死区。

## BLE 协议

默认 ATT MTU 足以容纳所有数据，无需大 MTU。UUID 为：

| 项目 | UUID | 操作 |
| --- | --- | --- |
| 服务 | `7f510001-1b15-4b85-9c13-8f08604a0001` | 广播 |
| 控制 | `7f510002-1b15-4b85-9c13-8f08604a0001` | 有响应写入 |
| 状态 | `7f510003-1b15-4b85-9c13-8f08604a0001` | 读取、通知 |

广播制造商数据为实验标识 `FF FF` 加两字节小端组号，名称在扫描响应中为 `GestureCar`。

控制帧为固定 12 字节、小端：

| 偏移 | 字段 |
| --- | --- |
| 0 | 协议版本 1 |
| 1 | bit0 姿态有效，bit1 按住使能，bit2 急停；其他位为 0 |
| 2–3 | uint16 递增序号，允许自然回绕 |
| 4–5 | int16 前后倾角，单位 0.01° |
| 6–7 | int16 左右倾角，单位 0.01° |
| 8–11 | uint32 发送端单调运行时间毫秒，允许自然回绕 |

长度、版本、标志或角度范围错误的帧被拒绝；重复/旧序号或未前进的发送时间不刷新超时。接收超时依据车端时钟，两个设备不需要对时。新连接重新建立序号基准。

状态为 12 字节：`[版本, 状态码, 车端故障, 0, pitch低, pitch高, roll低, roll高, A请求PWM, B请求PWM, D请求PWM, 0]`，PWM 为有符号 int8，倾角单位同控制帧。

## 验证与验收

从仓库根目录运行 `python esp-projects/gesture-common/test/run_tests.py`。它用 GCC 编译生产控制代码和 Fusion，不使用 ESP-IDF 桩头文件冒充完整构建。安卓目录运行 `gradlew.bat :app:testDebugUnitTest` 验证与 C 相同的黄金数据包及手机姿态方向。

实测顺序：

1. 电机断电填写接线，检查上拉、共地、供电、轴方向和车头挡板；保持 STBY 在 MCU 复位期间被下拉。
2. 不使能电机，检查 MPU 身份、静态姿态与校准完成状态。手机测试前后左右倾斜符号。
3. 架空车轮连接控制端：一直按住使能连接不应转动；松手回正后按下，再分别验证直行、后退、左转、右转与回正减速。
4. 测试松手、急停、发送端断电、蓝牙断连、安卓切后台/锁屏、MPU 断线，以及按住使能重连。故障后不得自动恢复。
5. 将小车架空后倾斜超过阈值，确认禁用输出；先回正，再重新使能。
6. 低速落地调整灵敏度，检查方向转换无突然反向驱动，然后分别完成三次推球入目标区域。

构建结果和现场验证必须区分；没有实机测试就不宣布接线正确、通信时延达标或推球成功。具体本次构建记录见 [VALIDATION.md](VALIDATION.md)。
